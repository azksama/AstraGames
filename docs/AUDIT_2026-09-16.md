# Revue globale — Astra 1.6.2

Revue du 16 septembre 2026. Version Android : `1.6.2`, code `20`, minSdk 26, targetSdk 36, schéma Room 8.

## Périmètre

La revue couvre tous les domaines de l’application (81 fichiers Kotlin de production après refactorisation), le manifeste, les ressources, les dépendances, les tests et le module Baseline Profile. Elle combine lecture des parcours, recherche des incohérences, compilation et analyse statique globale. Elle ne constitue pas une couverture d’exécution de chaque branche ou de chaque appareil Android.

## Pannes corrigées

### Édition de sauvegardes

Le chemin Ren’Py ne traitait pas correctement les archives ZIP et les références pickle ; modifier une valeur pouvait toucher une plage d’octets incorrecte. Le traitement est maintenant séparé du stockage Android, conserve les entrées annexes et recalcule les tailles de frames lors d’une édition. La signature du contenu précédent n’est pas réutilisée après modification.

MV et MZ ne partagent pas le même conteneur : MV utilise LZ-String, MZ base64/zlib. L’éditeur préserve le format détecté ainsi que les métadonnées JsonEx. Les fichiers `global` et `config` sont exclus de la liste des parties.

Pour RGSS, les entiers négatifs, les références d’objets/chaînes, les flux Marshal successifs et les clés numériques des dictionnaires ont été corrigés. Les parcours sont bornés et résistent aux cycles. Les formats/opcodes non pris en charge échouent avant l’écriture.

Chaque écriture est précédée d’un backup, suivie d’une relecture et d’une comparaison. Un échec tente de remettre l’original. Un hash de la version ouverte empêche d’écraser silencieusement une sauvegarde changée entre-temps. La restauration crée elle-même une copie de l’état courant.

Références de format vérifiées : [Ren’Py loadsave.py](https://github.com/renpy/renpy/blob/master/renpy/loadsave.py), [Ren’Py savetoken.py](https://github.com/renpy/renpy/blob/master/renpy/savetoken.py). Les fixtures sont synthétiques ; elles ne contiennent pas de partie utilisateur.

### Installation et retrait des mods

Les archives sont extraites dans un dossier privé avant publication dans le dépôt. Les chemins sortants, doublons de casse et archives excessives sont refusés. Un dossier d’emballage peut être retiré tout en préservant les racines `game`/`www`/`js`.

Les fichiers remplacés possèdent des backups distincts et vérifiés. Les conflits sont évalués avant retrait ; tous les backups nécessaires sont contrôlés avant restauration. Une installation incomplète reste visible avec son journal. Retirer la fiche d’un jeu tout en conservant ses fichiers exige d’abord de désinstaller/restaurer ses mods, afin de conserver un chemin de retour.

### Défauts transversaux

- Les cookies de session pouvaient accompagner une recherche sur un domaine externe. La recherche et les requêtes authentifiées sont désormais séparées.
- Les exports du catalogue courant pouvaient être rejetés à l’import et omettre des journaux. Le schéma 8 et ses fichiers privés sont pris en compte, sans perturber les triggers temporaires de Room.
- Des erreurs réseau pouvaient vider les mises à jour déjà connues. Les anciennes valeurs sont conservées pour les jeux dont la vérification échoue.
- Une copie accessible d’un jeu pouvait être interprétée comme son déplacement. Le scanner conserve désormais les deux entrées.

Les nouveaux tests couvrent notamment les écritures plus courtes, les fichiers modifiés après installation, l’absence de désinstallation partielle sur conflit, la sauvegarde du schéma 8, les URI SAF imbriquées, les références récursives, les noms de clés spéciaux, les ZIP invalides et les annulations de coroutines. Le fournisseur de documents de test existe uniquement dans la variante debug, protégé par `MANAGE_DOCUMENTS` ; il est absent de la release.

Les 41 avertissements lint restants portent sur des mises à jour disponibles de dépendances, des suggestions KTX, la migration kapt vers KSP et la forme de l’icône ronde. Des API de presse-papiers dépréciées et des avertissements Gradle 9 restent également à moderniser ; la compilation actuelle ne repose pas sur Gradle 9.

## Limites confirmées

- Aucun lancement d’une partie réelle sous JoiPlay ni test sur téléphone physique pendant cette revue. Les tests de stockage emploient des fichiers synthétiques et un fournisseur SAF de test.
- Formats chiffrés/propriétaires, classes/opcodes non pris en charge et mods spécifiques à un jeu : compatibilité à confirmer avec le jeu concerné. L’installation de fichiers ne configure pas automatiquement un plugin JavaScript isolé dans `plugins.js`.
- Ren’Py peut demander de confirmer le chargement d’une sauvegarde modifiée ; ce dialogue moteur n’a pas été validé en partie réelle.
- Les archives `.astra` chiffrées dépendent de la clé Keystore de l’installation. Elles ne sont pas portables après désinstallation ou vers un autre appareil. Le README précise cette limite.
- Les écritures sur SAF ne garantissent pas une atomicité matérielle face à une coupure de courant. Les backups et journaux permettent la récupération ; l’échec brutal d’un fournisseur physique n’a pas été reproduit.
- Les parcours communautaires authentifiés, toutes les traductions, les tablettes/pliables et les mesures de performance réelles ne sont pas validés exhaustivement. Les modules de benchmark ont été compilés, sans nouvelle génération de Baseline Profile.
