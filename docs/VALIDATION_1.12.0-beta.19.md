# Validation Wolf — 1.12.0-beta.19

Cette version traite plusieurs familles relevées dans le dernier diagnostic Seris : lectures d’état, souris, mouvements autonomes, références DB imbriquées, macros de chaînes, chemins de ressources et sauvegardes d’images. Le préflight continue d’inspecter le jeu entier et le secours Winlator est conservé.

## Diagnostic reçu et portée

La session `1791717976334-c09222ee-611a-48e4-b8f3-2ce7b56bd8c2`, Astra beta.18/code46, Android16/Samsung SM-S948B, s’arrête pendant la vérification des fonctions. Ses 241 cartes ont été inspectées et son rapport contient **375 incompatibilités distinctes**. Il ne s’agit pas d’un crash natif de Box64 ni d’un gameplay exécuté par le moteur natif.

L’inventaire dédupliqué se répartit ainsi :159 pages à déplacement autonome,61 fichiers d’image littéraux manquants,15 expressions de chemin avec références DB,38 macros,19 lectures d’état général,17 lectures souris,13 flags d’état,11 opcodes non implémentés,8 extensions de commande et34 autres variantes/références. Les données brutes des pages, flags et commandes originales ne sont pas jointes. Ces comptes décrivent les catégories du rapport reçu ; ils ne permettent pas de calculer honnêtement combien disparaîtront sur le jeu installé.

Les textes du rapport, noms de ressources privées et exports du désassembleur restent sous `build/`, exclus des sources et de l’APK. Aucun EXE du jeu utilisateur n’est exécuté, modifié ou distribué.

## Contrats livrés

- La commande124 utilise le catalogue partagé `WolfStateSupport.kt` : **149 emplacements numérotés,113 lectures admises et36 refus explicites**, y compris les slots réservés. Personnage28/31, position19/44, général36/36, image30/38. Les bits réservés, profils incompatibles et données manquantes restent contrôlés séparément. Le catalogue Sys/SysS reste183 identifiants,159 lectures admises et24 refus ; les deux catalogues désignent des API différentes.
- Les lectures d’état utilisent les paramètres réels des personnages, leur grille de sprite, collisions, page active, caméra/zoom, événements sous le pointeur, focus et souris. Android fournit la mémoire PSS/disponible et le temps du dernier rendu. Le temps CPU de la VM exclut l’attente d’un worker. Le pad Android utilise le profil de boutons compatible DirectInput d’Astra, sans simuler un périphérique Windows.
- Le host audio publie les positions et durées des décodeurs préparés, échantillonnées toutes les50ms. BGS respecte la voix sélectionnée par Sys99 ; MIDI utilise les ticks SMF, les autres formats les millisecondes. Une piste arrêtée ou remplacée n’expose pas les anciens temps du décodeur. Les lectures absentes renvoient0 selon le contrat natif.
- La souris physique transmet les trois boutons, molette, position et présence dans le viewport. La VM garde les fronts pendant une frame, la priorité gauche/milieu/droite et le compteur d’appui par tick logique. Le mode4 renvoie une durée réelle, pas un code de bouton. Focus perdu et changement de viewport libèrent l’entrée ; le tactile déjà porté conserve son parcours.
- Les mouvements de page2/3 utilisent les décisions aléatoire/approche observées, la cadence du jeu, le RNG partagé, les routes et collisions existantes. La fréquence de mouvement d’une page accepte le byte entier0..255 ; animation et vitesse restent0..6. La restauration applique les paramètres d’une page à l’objet personnage recréé même si le marqueur sauvegardé correspond déjà.
- Les propriétés d’image23..37 exposent ordre, ancrage, divisions, couleur, mélange, lien au défilement, durée/temps restant, délais et ID voisin. Les effets sont inclus seulement si le bit64 est demandé. L’animation utilise les unités du moteur à60 et30FPS ; la durée configurée reste lisible après la fin. La sauvegarde native **v23** conserve ces horloges et migre les tweens des versions antérieures. Les sauvegardes Windows restent distinctes.
- Les références DB imbriquées ne sont plus refusées après une unique passe syntaxique. Les valeurs, types et bornes DB réels sont encore contrôlés à la résolution. Les alias WOLFX existants et chemins relatifs au dossier du jeu sont examinés sans copier tout le jeu. Un fichier littéral réellement absent reste bloquant.
- Les macros ajoutées couvrent les fichiers graphiques réels des personnages/images, le type des champs DB, largeur logique/octet UTF-8 qualifiés et découpe inclusive de lignes. La syntaxe officielle `FIND_PATH_DIR4_SX=…` rejoint le résolveur existant. Les chaînes formatées de BYTE en mode conversion restent refusées tant que la reconstruction des codes compilés n’est pas portée.
- Le scan continue sur toutes les cartes même après le quota de512 diagnostics. Il indique alors une liste tronquée/incomplète. Les rapports de commande contiennent des operands numériques décimal/hexadécimal et bytes de page/extension bornés ; ils ne recopient pas les dialogues du jeu. L’aperçu reste court, le rapport exporté contient les détails conservés.

Les algorithmes et flags sont étayés par une analyse statique REA du Game.exe officiel Wolf3.729 épinglé par SHA-256, pas par du code source original. Références : [lectures d’état](wolf-native/STATE_READ_REA.md), [catalogue vérifiable](wolf-native/STATE_READ_COVERAGE.md), [mouvements](wolf-native/AUTONOMOUS_MOTION_REA.md), [texte et macros](wolf-native/TEXT_CODES_BETA19_REA.md). Les snapshots et exports REA privés sont conservés après fermeture des sessions ; les fichiers originaux ne sont pas altérés.

- **402 tests JVM moteur +246 tests JVM application =648 réussites**, aucun échec/erreur/ignore. Le lot inclut la matrice des256 champs de chacune des quatre catégories124, host réel vs état absent, boutons/molette/fronts/durée, audio périmé, géométrie du pointeur, flags d’effets, sauvegarde/reprise aux deux cadences et ancienne fixture v21. Les premières assertions de fixtures ont été corrigées pour respecter fin d’événement vs effacement, déclenchement action vs automatique et paramètres bruts d’effets ; les sorties initiales et finales restent séparées dans les preuves locales.
- **21 tests Python** du probe structurel passent. `python tools/wolf_system_audit.py --check` et `python tools/wolf_state_audit.py --check` vérifient les deux catalogues générés sans réseau. Les34 originaux du manifeste correspondent aux tailles et SHA-256 attendus.

Le lot se termine normalement en54,967s. Les7 cas ignorés ne sont pas comptés comme des réussites.

## Limites restantes

Les opcodes252/255/256/257, extensions non interprétées, macros de création/renommage d’événement et AUTO_RETURN, variantes de CSV/assignation/effets et certaines coordonnées/quadrilatères restent signalés. Les61 fichiers d’image littéraux et l’entrée de carte vide de SysDB ne sont pas ignorés arbitrairement. Les operands supplémentaires facilitent l’analyse d’un prochain rapport, sans désactiver le préflight.

Le jeu Seris complet n’est pas disponible localement. Il n’y a donc pas de preuve d’une partie native de ce jeu, de disparition des375 incompatibilités ou de30/60FPS sur le Samsung ARM64. En mode Automatique, une incompatibilité conservée conduit au secours Winlator ; en Natif forcé elle interrompt la préparation avec le diagnostic. La compatibilité du moteur reste partielle.
