# Audit traduction — 5 octobre 2026

## Périmètre inspecté

Tous les fichiers du package `app/src/main/java/fr/astragames/app/translation` ont été lus : `GameTranslationManager`, `RpgTextDocument`, `TranslationPatch`, `TranslationTiming` et `LocalTranslator`. Leurs tests JVM et les tests Android existants ont été examinés. Les interfaces `GameTranslationController` et `GameTranslationScreen` ont été examinées pour définir l’intégration ; leurs modifications sont gérées par l’audit UI général.

Les nouvelles responsabilités sont séparées : `ProtectedText` analyse les contrôles ; `TranslationJson` valide le JSON ; `ManualTranslationBundle` définit et vérifie l’échange ; `TranslationIo` borne les lectures, y compris les fournisseurs renvoyant zéro octet sans EOF. L’accès SAF et la coordination restent dans `GameTranslationManager`, les écritures et le rollback dans `TranslationPatch`.

## Préservation des jeux

L’extraction repose sur les champs que le moteur standard affiche ou utilise comme référence à un nom traduit. Les commandes ont été recoupées avec le [Game_Interpreter officiel MV](https://github.com/rpgtkoolmv/corescript/blob/master/js/rpg_objects/Game_Interpreter.js). La branche 402 est pilotée par son index numérique, qui reste inchangé ; son libellé est extrait pour garder un événement lisible. Pour 111, seul le cas acteur/nom (`parameters[0] = 4`, `[2] = 1`, texte en `[3]`) est extrait. Les scripts 355/655, les conditions JavaScript 111, les commandes de plugins 356/357, leurs paramètres, les commentaires, notes et chemins restent opaques.

| Source standard | Champs/commandes couverts |
| --- | --- |
| `MapNNN.json` | `displayName` et chaque `events[].pages[].list` |
| `CommonEvents.json`, `Troops.json` | Chaque `list` d’événement commun et chaque liste de page de combat |
| Listes d’événements | 401/405 texte normal/défilant ; 101 cinquième paramètre du locuteur MZ ; 102 choix ; 402 libellé ; 320/324/325 nom/surnom/profil ; 111 référence de nom d’acteur |
| `Actors`, `Classes`, `Enemies` | Noms ; surnoms et profils d’acteurs |
| `Items`, `Weapons`, `Armors`, `Skills` | Noms et descriptions ; `Skills.message1/message2` |
| `States` | Nom, `message1` à `message4` |
| `System` | `gameTitle`, `currencyUnit`, tableaux `armorTypes/weaponTypes/skillTypes/equipTypes`, `terms.basic/params/commands`, toutes les chaînes de `terms.messages`, y compris clés nouvelles |

La couverture système correspond aux lectures du [TextManager officiel MV](https://github.com/rpgtkoolmv/corescript/blob/master/js/rpg_managers/TextManager.js) et aux catégories de [termes documentées MZ](https://rpgmakerofficial.com/product/MZ_help-en/01_08_14.html). Les champs vides et emplacements `null` ne deviennent pas des textes à traduire, mais leur index et leur position restent intacts. Les noms utilisés comme identifiants par les conditions sont inclus pour donner un contexte complet à l’IA, avec protection explicite ; leur conservation ne compte pas comme échec ou traduction partielle.

Les contrôles standards MV/MZ, dont `\\`, `\V`, `\N`, `\P`, `\G`, couleurs/icônes, temporisations et `\PX/\PY/\FS`, sont testés. Le nom de locuteur et le texte défilant suivent les [commandes Messages MZ](https://rpgmakerofficial.com/product/MZ_help-en/01_10_01.html). Le traitement des séparateurs, dont le saut de page U+000C, a été recoupé avec [Window_Base officiel](https://github.com/rpgtkoolmv/corescript/blob/master/js/rpg_windows/Window_Base.js) et [Game_Message officiel](https://github.com/rpgtkoolmv/corescript/blob/master/js/rpg_objects/Game_Message.js). Le cache v2 continue d’être validé par le scanner courant ; le nouveau découpage autour des sauts de page ne réutilise pas l’ancienne clé incluant ces sauts.

L’import utilise les mêmes sauvegardes vérifiées, contrôles de conflits et journal que la traduction locale. Les fichiers sont tous relus et comparés à leur empreinte avant de préparer les modifications. Les sauvegardes sont créées et vérifiées avant de toucher les sources. Une écriture partielle tente une restauration immédiate ; son journal reste disponible si la restauration échoue. Le hachage est un contrôle de cohérence, pas une signature contre un acteur disposant déjà du droit de modifier à la fois le jeu et ses sauvegardes.

## Limites assumées

Le périmètre est MV/MZ et leurs données JSON standards. Les images, scripts, textes produits dynamiquement, fichiers de plugins personnalisés, Ren’Py et RGSS ne sont pas traduits. Les arguments de commandes inconnues sont volontairement opaques. Les marqueurs gardent un ordre strict afin de préserver les changements de couleur/format et l’ordre d’exécution. Une IA peut donc devoir reformuler sans réordonner ces marqueurs. Un service IA externe n’est jamais appelé par Astra pour ce mode.

L’expression « tous les textes » désigne ici toutes les occurrences des champs standards ci-dessus, et non toute chaîne JavaScript ou tout pixel du jeu. `MapInfos.name`, noms d’événements, de groupes, d’animations et de tilesets sont des identifiants d’édition, pas les libellés affichés par le moteur standard. Les noms d’éléments, de variables et d’interrupteurs sont omis parce que leur affichage personnalisé dépend de plugins ; modifier ces valeurs sans connaître leur usage peut changer un protocole ou un identifiant attendu. Les noms de ressources, `System.locale`, formules et scripts sont de la configuration ou du code, pas du texte de dialogue.

Les noms/profils déjà enregistrés dans d’anciennes sauvegardes ne sont pas migrés. Les groupes de noms utilisés par une condition standard sont donc conservés automatiquement dans leurs définitions, changements et comparaisons ; cette décision protège l’identité logique tout en laissant les profils et dialogues traduisibles. Les références nominales écrites dans du JavaScript ou un plugin ne peuvent pas être déduites de façon générique. Les commandes inconnues, y compris un nom de commande ASCII suivi sans séparateur d’un mot, restent opaques par prudence : l’extracteur ne devine pas la grammaire d’un plugin. Ces cas demandent une adaptation spécifique au jeu et empêchent de promettre une traduction intégrale de tout jeu MV/MZ personnalisé.

La compatibilité des alias d’URI entre fournisseurs distincts reste dépendante d’Android : aucun ID commun n’est défini pour deux fournisseurs exposant le même contenu. L’utilisateur choisit un nouveau fichier via CreateDocument ; la vérification que la destination est vide empêche également l’écrasement d’un contenu existant exposé par un autre fournisseur. Les protections supplémentaires couvrent les identités documentaires standard, les descendants détectables et les chemins locaux. L’atomicité entre vérification et ouverture du flux dépend du fournisseur SAF.
